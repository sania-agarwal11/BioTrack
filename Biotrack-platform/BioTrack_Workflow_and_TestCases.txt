  ROLES IN THE SYSTEM
  ───────────────────
  ADMIN                 — Full access to everything
  CLINICAL_TRIAL_MANAGER — Manages protocols, sites, patients, visits, notifications
  LAB_TECHNICIAN        — Creates/manages samples and lab results
  REGULATORY_OFFICER    — Views compliance reports and audit logs
  DATA_MANAGER          — Views audit logs and creates KPI reports
  RESEARCH_SCIENTIST    — Read-only access to compliance reports

  SECURITY MODEL
  ─────────────
  All endpoints except /api/v1/auth/** require a JWT Bearer token.
  Each service independently validates the token using the shared secret.
  Tokens are obtained from IAM Service /api/v1/auth/login.
  In Swagger: click the "Authorize" button → enter:  Bearer <your-jwt-token>

  SECTION 2 — APPLICATION WORKFLOW NARRATIVE
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

  PHASE 1 — IDENTITY & ACCESS MANAGEMENT (IAM Service)
  ─────────────────────────────────────────────────────
  The Admin first registers all platform users with appropriate roles.
  Each user logs in and receives a JWT token used for all subsequent calls.
  All mutations (create/update/delete users) are restricted to ADMIN role.

  PHASE 2 — CLINICAL TRIAL SETUP (Protocol Service)
  ──────────────────────────────────────────────────
  The Clinical Trial Manager creates a Protocol that defines the study.
  A Protocol has a title, phase (PHASE_I to PHASE_IV), start/end dates.
  Sites (clinical locations) are created and linked to the protocol.
  A Site has an investigator, a location, and a status (ACTIVE/INACTIVE).

  PHASE 3 — PATIENT ENROLLMENT (Patient Service)
  ───────────────────────────────────────────────
  The Clinical Trial Manager enrolls Patients into the study.
  A Patient is linked to a Protocol and a Site.
  Visits are scheduled for each patient — each visit records the date,
  status, site, protocol, and notes from the clinical encounter.

  PHASE 4 — SAMPLE COLLECTION & LAB ANALYSIS (Sample Service)
  ─────────────────────────────────────────────────────────────
  The Lab Technician collects and registers Samples (linked to patient/site/protocol).
  For each Sample, a Lab Result is recorded with test type, result value, and status.
  This represents the core data collection phase of the clinical trial.

  PHASE 5 — NOTIFICATIONS (Notifications Service)
  ────────────────────────────────────────────────
  The system sends EMAIL, SMS, or SYSTEM notifications to relevant users.
  EMAIL notifications trigger actual email delivery via Gmail SMTP.
  Notifications track read/unread status per user.

  PHASE 6 — ANALYTICS & KPI REPORTING (Analytics Service)
  ─────────────────────────────────────────────────────────
  The Data Manager creates KPI Reports for different tracking scopes:
  ENROLLMENT_RATE, SAMPLE_PROCESSING_RATE, or COMPLIANCE_SCORE.
  Reports capture metrics and a generated date for trend analysis.

  PHASE 7 — COMPLIANCE & AUDIT (Compliance Service)
  ──────────────────────────────────────────────────
  Every CREATE/UPDATE/DELETE across all services auto-generates an Audit Log
  entry in the Compliance Service via fire-and-forget OpenFeign calls.
  The Regulatory Officer reviews Audit Logs and Compliance Reports.
  Compliance Reports are manually created to summarise audit findings.

  SECTION 3 — HOW TO USE SWAGGER
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

  1. Start all services (Eureka first, then Gateway, then individual services).
  2. Open the Swagger URL for the service you want to test.
  3. Run the login step first to get your JWT token.
  4. Click the green "Authorize" button at the top right of Swagger UI.
  5. In the "bearerAuth" field enter:  Bearer eyJhbGci...  (your full JWT token)
  6. Click "Authorize" then "Close".
  7. Now all secured endpoints will automatically include your token.
  8. Follow the test steps below in ORDER — later steps depend on IDs
     returned by earlier steps (e.g., patientId, protocolId, siteId).

  NOTATION:
    [SERVICE]  = open that service's Swagger URL
    METHOD URL = the endpoint to expand and click "Try it out"
    AUTH       = which role's token to paste in Authorize
    BODY       = JSON to paste in the request body
    EXPECTED   = predicted HTTP status and response shape
